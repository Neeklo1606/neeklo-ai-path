# Архитектура neeklo.ru: цель и порядок перехода

Документ описывает, к какой структуре мы ведём код и в каком порядке туда идём.
Текущее состояние кода — в [CODE_AUDIT.md](CODE_AUDIT.md), карта функциональности — в [AUDIT.md](AUDIT.md).

## Почему не «переписать всё сразу»

Сайт работает и принимает заявки, тестов мало (16 кейсов на 40 тысяч строк), миграций БД нет,
а один файл `server/cms-server.mjs` обслуживает одновременно сайт, CRM, биллинг, Avito и Telegram.
Единовременная перестройка на такой базе — это гарантированный простой и потерянные заявки.
Поэтому переход разбит на этапы: каждый самодостаточен, проверяем и выкатывается отдельно.

## Целевая структура

```
server/
  cms-server.mjs          точка входа: конфигурация, middleware, подключение модулей
  routes/                 по одной области на файл: маршруты + валидация входа
    blog, videos, cases, prices, kp, media, pages, settings, crm, chat, avito, telegram, billing
  services/               работа с внешним миром: LLM, Qdrant, Avito API, Telegram, Clero
  lib/                    общее: авторизация, лимиты, ошибки, логирование
prisma/
  schema.prisma + migrations/   изменения схемы только миграциями
src/
  pages/                  страницы-роуты, без запросов «руками»
  components/             презентация; общее состояние — через хуки
  features/               будущее: блок функциональности = компоненты + хуки + типы
  hooks/useCmsQuery.ts    единая точка чтения публичного API
  lib/api/                клиенты API: публичный и админский
```

**Правила, которые уже действуют:**
1. Новая область — новый модуль в `server/routes/`, а не строки в `cms-server.mjs`.
2. Чтение публичного API — только через `useCmsQuery`; у каждого блока есть состояния загрузки, ошибки и повтора (`DataState`).
3. Зависимости модулю передаются явно (`registerXRoutes(app, { prisma, requireAuth })`) — модуль не лезет в глобальные объекты.
4. Ошибку наружу отдаём понятным текстом, подробности — в лог.

## Границы, которые не двигаем без отдельного решения

Avito и Telegram (`server/telegram-bot.mjs`, `server/services/avito-agent.mjs`, вебхуки в `cms-server.mjs`),
таблицы `crm_chats`, `crm_leads`, `service_prices`. Любая правка там согласуется отдельно: на этих путях
живут деньги клиента — входящие заявки и диалоги.

## Как проверять каждый этап

```bash
npm run lint && npx tsc --noEmit -p tsconfig.app.json && npm test && npm run build
node server/cms-server.mjs & npx vite --port 8090      # локальный стек
```

Эталон на момент этапа 4: типы 20 ошибок, линтер 13, тесты 16/16, сборка проходит.
Эти числа должны только уменьшаться.
